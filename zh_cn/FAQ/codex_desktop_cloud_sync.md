# Codex 桌面端连接云端（传送）指南

> 适用于「在本地桌面端开发，同时把会话/代码/任务与云端环境打通」的常见场景。

## 1) 先确认你说的“传送”是哪一种

通常会有三类：

1. **账号与会话同步**：桌面端登录后，同步历史会话和身份。
2. **代码传送到云端执行**：把本地仓库或当前目录映射到云端运行环境。
3. **把本地服务暴露给云端/浏览器**：端口转发、隧道、反向代理。

如果你是第 2 类（最常见），按下方步骤配置即可。

## 2) 标准打通步骤

1. **升级桌面端到最新版本**（旧版本常见 token 过期与连接协议不兼容）。
2. **使用同一 OpenAI 账号登录桌面端与云端控制台**。
3. **在桌面端绑定工作目录**：打开仓库根目录，确保 Git 可正常识别。
4. **配置云端连接方式**（通常为 API Key / OAuth / 组织工作区）。
5. **开启远程执行或云端会话**：确认目标 region、runtime、镜像/依赖。
6. **验证传送是否成功**：
   - 拉起一个最小命令（如 `pwd`、`git status`）。
   - 执行一次短任务，确认结果可回传。

## 3) 常见故障排查

- **一直转圈或连接失败**
  - 退出重新登录账号。
  - 检查公司代理/防火墙是否拦截桌面端到云端的 TLS。
  - 同步系统时间（证书校验对时间漂移很敏感）。

- **显示已连接但仓库没同步**
  - 检查是否打开了正确目录（不是父目录或空目录）。
  - 确认 `.git` 存在且当前分支可读。
  - 重新触发一次“上传/同步当前工作区”。

- **云端跑不起来本地项目**
  - 在云端补齐依赖（Python/Node/Java 版本、包管理器锁文件）。
  - 明确工作目录与启动命令。
  - 如需访问本地服务，配置端口转发。

## 4) 建议的最小验证清单

- [ ] 桌面端与云端使用同一账号。
- [ ] 本地仓库已在桌面端正确打开。
- [ ] 云端环境可执行 `git status`。
- [ ] 至少一条命令结果能回传到桌面端。
- [ ] （可选）端口转发可访问本地服务。

## 5) 你可以直接给我这 4 条信息，我帮你精准定位

1. 你的系统（macOS/Windows/Linux）
2. 桌面端版本号
3. 错误提示全文（或截图中的关键报错）
4. 你卡在“登录、同步目录、远程执行、端口转发”哪一步
